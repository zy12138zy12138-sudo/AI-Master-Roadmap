# Personal OS AI 决策与 Prompt 系统 V2.0

> 基线日期：2026-08-05
> 适用阶段：Day 8—Day 10 及后续 AI 迭代
> 上位文档：《Personal OS MVP 总体方案 V3.2》

## 一、产品目标

AI 不是普通聊天框，而是 Personal OS 的决策层。它基于目标、项目、任务、可用时间、精力与复盘，生成可解释的执行方案；所有数据修改在用户确认后才应用。

核心闭环：

```text
目标/项目/任务 → 计划 → 今日执行 → 每日复盘
→ DeepSeek AI 决策 → 用户确认 → 更新计划与任务
```

## 二、第一阶段决策范围

1. 今日决策：选择核心任务、推荐 P0—P3、安排顺序、控制任务量；
2. 任务调整：建议继续、延期、拆分、降级或取消；
3. 障碍分析：识别任务过大、手机干扰、精力不足、情绪影响和规划过度；
4. 项目推进：识别长期停滞项目并给出最小下一步；
5. 反馈调整：根据复盘提出一条可验证的行为调整。

周计划、周复盘和长期趋势分析在基础闭环稳定后扩展。

## 三、权限与确认规则

| 操作 | 权限规则 |
|---|---|
| 分析、解释、排序建议 | 可直接展示 |
| 新增、拆分、延期、改日期、改优先级 | 展示修改前后对比，用户确认后写入 |
| 删除任务 | 单独明确确认 |
| 改变长期目标或项目状态 | 单独明确确认 |
| API 失败、超时、输出不合法 | 不修改任何数据 |

AI 不得静默执行，不得用模糊的“优化计划”按钮一次性覆盖未知范围的数据。

## 四、技术架构

```text
Personal OS App
→ 发送最小必要上下文
→ 安全服务端代理
→ DeepSeek API
→ JSON Schema 校验
→ App 展示决策与差异
→ 用户确认
→ 本地 SQLite 事务写入
```

安全要求：

- DeepSeek API Key 只保存在服务端环境变量；
- Key 不进入 App、源码、Git、客户端日志或错误提示；
- 服务端配置请求超时、频率限制、错误映射和最大输入/输出长度；
- 默认不发送无关个人信息，只发送完成当前决策所需数据；
- 结构化输出校验失败时允许安全重试一次，仍失败则返回可理解的中文错误；
- 写入本地数据必须使用事务，失败时整体回滚。

## 五、AI 输入结构

```json
{
  "request_type": "daily_decision",
  "date": "YYYY-MM-DD",
  "available_time_blocks": [],
  "energy_context": {},
  "constraints": [],
  "goals": [],
  "projects": [],
  "tasks": [],
  "recent_reviews": [],
  "known_blockers": []
}
```

任务至少包含：`id`、标题、项目、日期、P0—P3、完成状态和可选预计时长。最近复盘只取完成当前判断所需的有限时间范围。

## 六、AI 输出结构

```json
{
  "summary": "string",
  "core_task_ids": [],
  "recommended_order": [],
  "actions": [
    {
      "action_id": "string",
      "action_type": "reprioritize|reschedule|split|create|delete|keep",
      "target_task_id": "string|null",
      "proposed_changes": {},
      "reason": "string",
      "first_step": "string",
      "confirmation_level": "normal|explicit"
    }
  ],
  "execution_risk": "string",
  "anti_procrastination_adjustment": "string"
}
```

输出规则：

- 不得引用不存在的任务 ID；
- 不得把全部任务设为 P0/P1；
- 每项修改必须有具体理由；
- `delete` 和长期目标变更必须标记为 `explicit`；
- 无足够信息时返回保守建议，不虚构事实。

## 七、System Prompt 基线

```text
你是 Personal OS 的个人执行决策引擎。

你的目标不是安排更多任务，而是在用户真实的时间、精力和约束下，帮助其选择最有价值且能完成的行动。

决策原则：
1. 优先保证 P0 和少量 P1，控制当日任务总量。
2. 发现任务过大时，优先拆成可立即开始的第一步。
3. 结合近期复盘识别重复阻碍，但不得把推断当成事实。
4. 每项建议必须说明理由、第一步和所需确认级别。
5. 删除任务、改变长期目标属于高影响操作，必须要求明确确认。
6. 不得虚构任务、完成记录、时间、精力或健康状态。
7. 只返回符合给定 JSON Schema 的内容，不输出 Markdown 或额外解释。
```

## 八、主要请求模板

### 8.1 今日计划决策

目标：从当天及逾期任务中选择合理任务量，输出核心任务、执行顺序、第一步与必要调整。

### 8.2 未完成任务分析

目标：结合最近复盘判断更可能的阻碍，提出继续、拆分、延期或取消建议，并明确这是基于数据的推断。

### 8.3 项目下一步

目标：对长期未推进项目给出一个最小可执行动作，不自动扩大项目范围。

### 8.4 每日复盘反馈

目标：总结完成情况，识别一个重复阻碍，并给出明天可验证的一条调整动作。

## 九、页面交互

AI 决策页至少包含：

- 决策摘要；
- 今日核心任务；
- 推荐顺序；
- 建议动作列表；
- 修改前后对比；
- 逐项接受、全部采用、修改后采用、拒绝；
- 高影响操作二次确认；
- 加载、超时、失败、重试和无网络状态。

采用方案后显示实际成功写入的动作数；部分失败不得伪装为全部成功。

## 十、数据记录

建议新增：

- `ai_decisions`：请求类型、上下文摘要、模型、状态、结构化结果、生成时间；
- `ai_decision_actions`：动作类型、目标任务、建议值、确认状态、应用状态与时间。

默认不保存 API Key，不保存不必要的完整自然语言上下文。保存决策记录的目的，是支持审计、撤销判断和后续反馈分析。

## 十一、Day 8—Day 10 交付

| 阶段 | 交付 |
|---|---|
| Day 8 | 安全服务端代理、DeepSeek API 服务、密钥配置、超时与错误处理、最小连通性测试 |
| Day 9 | 上下文汇总、System Prompt、JSON Schema、结构化结果校验、AI 决策展示与差异预览 |
| Day 10 | 逐项/全部确认、本地事务写入、决策记录、失败回滚、真机回归与文档结项 |

## 十二、验收标准

- App 和 Git 中均不存在 DeepSeek API Key；
- AI 能基于真实任务和复盘返回有效结构化结果；
- 无效 ID、非法优先级和不合规结构被拦截；
- 用户确认前，本地任务数据无任何变化；
- 拒绝建议后不写入；
- 删除和长期目标变更必须单独确认；
- 请求失败、超时或写入失败不会留下半完成状态；
- Reload 和重启后，已确认写入的数据与决策记录保持一致。

## 十三、明确排除

- 普通聊天机器人；
- 客户端直连并暴露 API Key；
- 无确认自动改计划或删除任务；
- AI 自动训练；
- AI 自主改变长期目标；
- 在 Day 5—Day 7 基础闭环完成前提前接入 AI。
