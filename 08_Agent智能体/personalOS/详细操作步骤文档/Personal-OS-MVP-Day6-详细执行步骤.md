## 四、Day 6 功能详细定义

### 4.1 计划任务进入今日

- 今日页每次获得焦点时重新生成本地日期；
- 只查询固定项目下 `scheduled_date = today` 的任务；
- 计划页今天的任务与今日页是同一条 SQLite 记录；
- 不使用 `INSERT` 复制“今日任务”；
- 在任一页面编辑、完成或删除后，另一页面重新聚焦立即同步；
- 首次加载显示 loading，后续聚焦静默刷新；
- 保留请求编号和卸载保护，旧查询不得覆盖新结果。

### 4.2 未完成任务自动顺延

正式规则：

| 场景 | 结果 |
| --- | --- |
| 昨天已完成 | 留在昨天 |
| 昨天未完成 | 更新到今天 |
| 连续多天未打开 | 所有过期未完成任务一次性更新到今天 |
| 今天已有任务 | 合并展示，不覆盖 |
| 未来任务 | 不处理 |
| 多次进入今日页 | 不重复、不新增 |

数据库条件：

```sql
project_id = ?
AND scheduled_date < ?
AND completed = 0
```

顺延只允许更新：

- `scheduled_date`；
- `updated_at`；
- 为保证同级稳定排序所必需的 `sort_order`。

必须保持：

- `id`；
- `project_id`；
- `title`；
- `priority`；
- `completed`；
- `created_at`。

顺延必须通过数据库模块中的事务函数完成，使用参数绑定。页面中不得直接拼写复杂 SQL。重复执行后，已移动到今天的任务不再满足条件，因此必须天然幂等。

### 4.3 周视图

计划页增加“日 / 周”视图切换，或在现有计划页中增加清晰的周计划区域。最终交互形式由只读检查基于当前 UI 决定，但必须满足：

- 默认进入时仍保持现有日视图行为；
- 周视图默认显示包含本地今天的周；
- 一周以周一开始、周日结束；
- 支持上一周、本周、下一周；
- 标题显示周日期范围，例如“8月3日—8月9日”；
- 按周一至周日分组展示任务；
- 每条任务显示优先级、标题和完成状态；
- 当天有明确但克制的视觉标识；
- 空日期保持稳定占位，不因查询刷新造成布局抖动；
- 周任务来自 SQLite 日期范围查询，不加载全库后前端筛选；
- 排序为日期升序，每日内部 P0→P1→P2→P3，同级 `sort_order ASC`；
- 周视图至少支持点击某一天切回该日日视图；
- 日视图原有新增、编辑、完成、删除和日期选择能力必须保留。

### 4.4 本周目标

本周目标是周级数据，不伪装成普通任务。最小功能：

- 周视图顶部展示本周目标；
- 可新增目标；
- 可编辑目标文字；
- 可删除目标，删除前二次确认；
- 支持多条目标，建议最多 3 条，但 MVP 不做强制数量限制；
- 标题 trim 后不能为空，建议限制 100 字；
- 目标顺序稳定；
- 上一周和下一周拥有各自独立目标；
- Reload 和重启后保留。

若当前数据库没有周目标结构，允许新增最小 `weekly_goals` 表并顺序升级数据库版本。禁止把周目标存入组件状态、硬编码数组或 AsyncStorage 形成第二数据源。

建议字段由 Codex 只读检查后定稿，至少需表达：

```text
id
project_id
week_start_date
title
sort_order
created_at
updated_at
```

必须建立项目与周开始日期的查询索引；SQL 使用参数绑定；迁移放在现有迁移链中并具备事务回滚。若新增表，数据库版本不再强行保持 V3，应安全升级为下一个连续版本。

### 4.5 周统计

周视图实时展示：

| 指标 | 计算方式 |
| --- | --- |
| 本周任务总数 | 一周日期范围内全部任务数 |
| 已完成数 | `completed = 1` |
| 未完成数 | 总数－已完成数 |
| 完成率 | 已完成数 ÷ 总数 × 100% |

规则：

- 无任务时完成率显示 `0%`，不得出现 `NaN`；
- 统计必须与周视图任务列表使用同一日期范围；
- 顺延任务移动后，原周与目标周统计都应按当前数据实时变化；
- 本轮不保存统计快照，避免冗余；
- 本轮不实现执行评分、习惯完成率和复盘结论，这些属于 Day 7。

## 十四、选择性 Git 提交

```powershell

git add -- "src/database/tasks.ts"
git add -- "src/database/migrations.ts"

git diff --cached --stat
git diff --cached --check
git status --short

git commit -m "完成 Day 6 任务衔接与周计划"
git push
```

只暂存真实修改且已授权的文件；不存在的文件不要执行对应命令。禁止 `git add .`。

提交后执行：

```powershell
git status --short --branch
git log -3 --oneline --decorate
```
