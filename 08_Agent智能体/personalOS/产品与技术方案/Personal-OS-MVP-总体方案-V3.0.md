## 二、产品定位

Personal OS 是一款个人自用的 iPhone 执行管理 App，核心目标是把长期目标转化为可执行计划，通过任务、复盘和反馈形成闭环，重点解决：

- 规划投入过多、开始执行较慢；
- 任务过大导致拖延；
- 手机、情绪和精力波动影响执行；
- 完成结果缺少连续记录与反馈；
- 多个长期项目之间缺少统一优先级。

产品成功标准不是功能数量，而是用户能持续完成：

```text
目标 → 计划 → 今日任务 → 执行 → 复盘 → 调整
```

## 三、用户与使用边界

- 单人自用，不商用；
- 在 iPhone 的 Expo Go 中运行；
- 本地优先，不依赖后端；
- 不发布 App Store；
- 不建立账号、登录、支付或云同步；
- 不保存 DeepSeek 账号、密码或对话内容；
- App 不显示 ChatGPT 名称或入口；
- MVP 不接 OpenAI、DeepSeek 或其他模型 API。

## 四、产品结构

采用“功能入口＋项目归属”的混合结构。

### 4.1 底部功能入口

| Tab | 核心职责 |
|---|---|
| 今日 | 查看并执行当天任务 |
| 计划 | 安排未来任务与日期 |
| 复盘 | 记录完成情况、阻碍和改进 |
| 我的 | 管理基础设置、项目与数据入口 |

### 4.2 数据归属关系

```text
长期目标 → 项目 → 计划/任务 → 每日复盘
```

可管理的项目包括但不限于 Personal OS App、新疆旅行、健康管理、英语学习、万万酱和职业发展。项目管理功能不提前塞入 Day 4，待计划页闭环后再评估。

## 五、任务优先级 V1.0

| 级别 | 定义 | 使用约束 |
|---|---|---|
| P0 | 当天必须完成，不完成会产生明确影响 | 每天建议 1—2 项 |
| P1 | 推动核心目标的重要任务 | 每天建议 2—3 项 |
| P2 | 常规执行任务，可调整日期 | 新任务默认值 |
| P3 | 低收益、提醒或有余力再做 | 可延期或删除 |

展示与排序规则：

1. 任务优先按 `P0 → P1 → P2 → P3` 展示；
2. 同一优先级内保持 `sort_order ASC`；
3. 已完成状态不改变任务优先级；
4. 默认优先级为 P2，避免普通任务被误标为重要任务；
5. P0 数量限制先通过产品提示实现，不在 MVP 阶段做强制拦截。

### 7.2 计划页

MVP 最小闭环：

- 查看未来日期任务；
- 新建计划任务；
- 选择任务日期；
- 修改日期和优先级；
- 将计划任务纳入对应日期的今日列表。

### 7.3 复盘页

MVP 最小闭环：

- 当日计划数、完成数和完成率；
- 当日自评分；
- 未完成原因；
- 执行阻碍；
- 今日做得最好的一件事；
- 明日改进动作；
- 保存本地复盘记录。

### 7.4 我的页

MVP 仅保留必要信息与入口，项目管理、数据导出和设置根据 Day 7 后实际需求排期。

## 八、数据库方案 V2 基线

```text
数据库：personal-os.db
当前版本：2
数据表：projects、tasks
日期：本地时区 YYYY-MM-DD
今日查询：project_id + scheduled_date
排序字段：sort_order
复合索引：project_id、scheduled_date、sort_order
任务 ID：SQLite randomblob(16)
```

今日任务最终查询：

```sql
WHERE project_id = ?
  AND scheduled_date = ?
ORDER BY sort_order ASC
```

优先级字段继续使用现有 `TEXT`，扩展 P0—P3 不单独升级数据库版本。只有新增计划或复盘表等真实结构变化时，才评估数据库 V3。

候选后续表：

- `daily_reviews`：每日复盘主体；
- `review_metrics`：如确需结构化指标再增加；
- 是否需要独立 `plans` 表由 Day 5 只读检查决定，优先复用带未来日期的 `tasks`。

## 九、技术架构

统一技术基线：

```text
Windows
+ VS Code
+ Codex
+ Expo SDK 54
+ React Native
+ TypeScript
+ Expo Router
+ expo-sqlite 16.0.10
+ iPhone Expo Go
+ 本地 SQLite
```

明确排除：

- SwiftUI、Xcode、Mac 专属开发链；
- 后端服务器、账号系统与云同步；
- OpenAI API、DeepSeek API 与 API Key；
- 新 ORM、全局状态框架或不必要 UI 框架；
- 为单一小功能升级 Expo SDK。

工程原则：

- 数据访问集中在数据库模块；
- SQL 使用参数绑定；
- 迁移顺序执行并由 `PRAGMA user_version` 管理；
- 日期统一复用本地日期工具；
- 页面不维护第二份固定任务数据源；
- 每次开发限定文件范围并选择性 Git 暂存。

## 十、DeepSeek 协作方案

产品内统一使用“DeepSeek 快捷助手”，不显示 ChatGPT。

```text
App 汇总结构化任务/计划/复盘
→ 一键复制
→ 打开 https://chat.deepseek.com/
→ 用户粘贴内容
→ DeepSeek 输出分析与行动建议
→ 用户决定如何调整 App 中的计划
```

技术边界：

- 使用系统外部链接能力打开 DeepSeek 官方对话页面；
- 跳转失败时显示中文提示；
- 不内嵌网页、不自动登录；
- 不自动发送内容；
- 不读取 DeepSeek 返回内容；
- 不保存账号密码；
- 不接 DeepSeek API。

## 十一、AI 决策与反馈模型定位

### 11.1 决策引擎

MVP 只生成结构化上下文，由 DeepSeek 辅助判断。输入至少包含：

- 当前长期目标与项目；
- 当日可用时间和精力；
- 待办任务、日期和优先级；
- 最近未完成原因；
- 当日特殊限制。

输出要求：当日 P0/P1 建议、任务顺序、可推迟项、风险和第一步行动。

### 11.2 目标权重模型

保留“收益、紧急性、长期价值、成本、风险”等维度作为人工决策参考，MVP 不开发自动评分算法。

### 11.3 执行评分模型

复盘页具备真实数据后再计算，建议最低维度：

- 完成率；
- P0 完成情况；
- 开始执行及时性；
- 计划合理性；
- 主观精力和阻碍。

评分用于识别执行问题，不用于惩罚或单纯追求高分。

### 11.4 反馈学习引擎

MVP 由 DeepSeek 基于用户复制的近期复盘进行分析，识别重复阻碍并输出一条可验证的调整策略。App 暂不自动训练模型或保存 AI 推断。

## 十二、Prompt 系统 V3.0

结构化复制内容统一为：

```text
【分析目标】
请根据以下 Personal OS 数据，帮我确定优先级并给出可直接执行的方案。

【日期与可用时间】
...

【当前项目与目标】
...

【任务列表】
- [P0/P1/P2/P3] 任务｜日期｜完成状态

【近期复盘】
...

【已知阻碍】
任务过大 / 手机分心 / 情绪 / 精力不足 / 其他

【输出要求】
1. 今日最重要任务；
2. 推荐执行顺序；
3. 应延期或删除的任务；
4. 每项任务的第一步；
5. 一个降低拖延的调整动作。
```

App 只负责生成与复制，用户主动粘贴至 DeepSeek。
