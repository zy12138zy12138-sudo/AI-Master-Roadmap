## 一、技术决策结论

Personal OS 继续采用“**本地优先、单人自用、渐进扩展**”架构。先建立项目、周节奏、复盘和状态数据的真实闭环，再增加 AI 决策能力。

当前闭环：

```text
项目归属（待补齐） → 任务安排 → 今日执行 → 未完成自动顺延
→ 每日复盘 → 执行结果
```

目标闭环：

```text
长期目标 → 项目 → 周目标 / 任务 → 今日执行 → 每日复盘
→ 周复盘与执行反馈 → 习惯与状态数据 → AI 决策建议 → 用户确认
```

这意味着：**本轮不接入 DeepSeek API，也不建设服务端。**V1.4 的 AI 助手先采用“跳转 DeepSeek + 可复制上下文”的无 API 方案；仅在连续使用至少 4 周、确认真实需求后，再单独评估 API、服务端与云端能力。

## 三、已实现数据与工程规则

### 3.1 数据库

- 数据库：`personal-os.db`；
- 已验收版本：V3；后续迁移继续通过 `PRAGMA user_version` 顺序执行；
- 当前核心表：`projects`、`tasks`、`daily_reviews`；
- 任务使用唯一 `project_id` 归属、`scheduled_date`（本地 `YYYY-MM-DD`）、`priority`（P0—P3）与 `sort_order`；
- SQL 一律参数绑定，数据写入失败不得显示成功；迁移与多步写入使用事务。

### 3.2 已验收行为

- 今日页与计划页读取同一份任务数据，不复制任务；
- 未完成的过期任务自动顺延到今天；完成状态不会回写原历史日期；
- 排序固定为 P0 → P1 → P2 → P3，同级按 `sort_order`；新任务默认 P2；
- 复盘未保存时展示实时统计；首次成功保存后冻结统计快照；
- 历史已完成任务取消完成前二次确认；
- 复盘同项目同日期唯一、UPSERT 更新、保存锁与异步旧请求保护均已验收；
- 所有业务日期统一复用本地日期工具，不以 `toISOString()` 直接生成日期。

## 五、V1.1：项目与周目标的技术方案

### 5.1 项目管理

- `projects` 是任务、周目标和复盘的唯一归属源；不建立第二套项目缓存；
- 在“我的”页提供项目列表、新增、编辑与归档；归档为软状态，不删除历史任务与复盘；
- 新增任务可选择活跃项目；今日/计划默认“全部项目”，可筛选单项目；
- 升级中必须保留默认项目与全部已有任务数据；
- 项目不做多层级、成员、预算、进度百分比、看板或甘特图。

### 5.2 周目标

- 周目标属于项目，以本地周起止日期标识；一个项目每周允许多条目标；
- 目标只记录名称、状态、排序与必要时间字段；任务可关联但不强制；
- 不以“完成任务数”自动改写周目标状态；由用户明确完成；
- 不开发复杂 OKR、权重、自动进度和跨周复制。

### 5.3 今日复盘卡片

- 今日页只展示复盘是否已保存、摘要和“去复盘/查看复盘”入口；
- 编辑、首次保存确认、统计快照仍只存在于复盘 Tab；
- 不建立第二套复盘表单、统计计算或数据库记录。

## 六、V1.2—V1.3：反馈数据的技术方案

### 6.1 周复盘

- 周复盘只汇总已存在的任务执行结果、已保存每日复盘与周目标；
- 每次展示统一按同一周范围查询，避免跨周或 UTC 边界；
- 保存的周复盘文字与确认结论独立存储；若后续任务被修正，不静默改写历史确认内容；
- 先做文字反馈与少量真实指标，不做复杂仪表盘。

### 6.2 习惯与状态

- 习惯定义与每天的完成记录分表保存；每日一条记录应有唯一约束；
- 精力、情绪、专注、手机干扰等以有限枚举/简单数值记录，不能假装精确；
- 执行评分仅基于已采集数据计算，并在界面说明依据；数据不足时显示空状态；
- 不加入提醒通知、连续天数竞赛、自动惩罚或隐性行为推断。

## 七、V1.4：无 API 的 AI 决策助手

产品名称统一为“AI 决策助手”，不显示 ChatGPT。此阶段通过 DeepSeek App/网页承接分析，不由 Personal OS 直接调用模型。

```text
App 汇总最小必要上下文
→ 生成可复制 Prompt
→ 跳转 DeepSeek
→ 用户获得建议
→ 用户在 App 手动新增/编辑/完成任务或记录结论
```

要求：

- 上下文只包含当前决策所需的项目、任务、近期复盘、周目标和状态摘要；
- 不嵌入 Key、账号或密码；不将个人数据静默上传；
- AI 建议不自动写入 SQLite；用户必须在 App 内确认并手动落实；
- Prompt 输出优先要求“核心任务、理由、第一步、风险和可选调整”，避免模糊鸡汤；
- 无法复制或跳转时，只显示可阅读的 Prompt，不影响本地任务功能。

## 八、V2.0 以后：API 的准入条件

仅同时满足以下条件才评估 DeepSeek API + 安全服务端代理：

1. 已连续使用 App 至少 4 周；
2. 项目、周目标、每日/每周复盘与状态数据已形成稳定结构；
3. 无 API 助手无法满足高频、重复的分析需求；
4. 用户明确愿意承担 API 成本与网络依赖；
5. 确认需要保存 AI 决策记录。

届时的目标架构为：

```text
App → 最小必要上下文 → 安全服务端代理 → DeepSeek API
→ Schema 校验 → 建议与差异展示 → 用户确认 → SQLite 事务写入
```

API Key 只能在服务端环境变量中；任何建议在确认前不得改动本地数据。服务端、限流、超时、审计表与 Schema 校验均是未来独立版本范围，当前不创建。

## 九、通用开发与验收规范

1. 每次开发先只读检查现有表、数据访问层、页面数据流和迁移版本。
2. 范围只覆盖当期版本；不重构已验收功能，不清空真机数据库。
3. 数据访问集中在 `src/database`；页面不维护第二份固定业务数据。
4. 每次改动完成后执行 TypeScript、Lint、差异检查，并在 iPhone 上验证持久化与重启。
5. 重点回归：本地日期、自动顺延、优先级排序、今日重点、复盘快照、历史任务确认。
6. 通过真机验收后再由老板确认是否选择性暂存、提交和推送。

## 十、当前不做清单

- 云账号、登录、多设备同步、共享协作；
- 系统通知、复杂重复任务、拖拽排序、子任务和任务依赖；
- 复杂项目看板、甘特图、自动进度、OKR 权重；
- API 服务端、客户端 API Key、自动 AI 改计划；
- App Store 发布、商业化、深色/浅色主题切换。
