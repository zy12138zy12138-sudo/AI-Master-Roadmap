## 二、本次验收范围

Day 4 在 Day 3 今日任务管理能力基础上，完成以下功能：

1. 数据库由 V2 安全升级至 V3。

## 五、数据库与数据安全验收

### 5.1 数据库版本与迁移路径

最终数据库版本为 V3：

```text
现有数据库：2 → 3
新安装：0 → 1 → 2 → 3
```

V2→V3 迁移通过临时表重建 `tasks` 表，将优先级约束扩展为：

```sql
CHECK (priority IN ('P0', 'P1', 'P2', 'P3'))
```

迁移保留以下字段：

- `id`
- `project_id`
- `title`
- `priority`
- `completed`
- `scheduled_date`
- `sort_order`
- `created_at`
- `updated_at`

迁移完成后重新建立原有索引，并在全部检查通过后设置 `user_version = 3`。任一步骤失败时事务整体回滚，避免产生半迁移状态。

### 5.2 编辑优先级的数据影响

实际更新语句为：

```sql
UPDATE tasks
SET title = ?, priority = ?, updated_at = ?
WHERE id = ? AND project_id = ?
```

数据库级核验结果：

| 字段 | 编辑优先级后的结果 |
| --- | --- |
| `priority` | 按用户选择正确修改 |
| `updated_at` | 正常刷新 |
| `title` | 未编辑标题时保持不变 |
| `scheduled_date` | 保持不变 |
| `completed` | 保持不变 |
| `sort_order` | 保持不变 |
| `project_id` | 保持不变 |
| `created_at` | 保持不变 |
| `id` | 保持不变 |

说明：页面未直接展示 `scheduled_date`，因此日期通过代码检查与数据库级验证确认，而非通过页面目视核对。

## 七、主题模式产品决策

Personal OS 不提供深色模式与浅色模式切换功能，当前版本及后续版本均不规划该功能。

因此：

1. 删除所有“切换浅色/深色模式”的验收要求。
2. 不新增主题切换入口、系统主题跟随设置或相关配置。
3. 后续页面与组件仅需在产品当前固定主题下保证清晰、统一和可读。
4. 此项属于明确的产品范围决策，不作为 Day 4 缺陷或遗留需求。
