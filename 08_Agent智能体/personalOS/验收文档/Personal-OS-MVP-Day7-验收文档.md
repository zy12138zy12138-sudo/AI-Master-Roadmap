## 四、代码级验证结果

### 4.1 复盘统计刷新与快照规则

- [x] 复盘 Tab 每次从失焦变为聚焦时重新读取当前日期。
- [x] 当前日期没有复盘记录时，重新查询真实任务并计算实时统计。
- [x] 当前日期已有复盘记录时，读取首次成功保存时的统计快照。
- [x] 后续任务变化不自动覆盖已保存快照。
- [x] 再次编辑复盘文字、自评分等内容不重算统计快照。
- [x] 页面卸载后不更新状态。
- [x] 快速切换日期或 Tab 时，旧异步请求不能覆盖当前页面。

### 4.2 数据库一致性

- [x] `daily_reviews` 对 `project_id + review_date` 建立唯一约束。
- [x] 重复保存使用 `ON CONFLICT(project_id, review_date) DO UPDATE`。
- [x] 读取逻辑使用明确的项目和日期条件，不依赖无序 `LIMIT 1` 掩盖重复数据。
- [x] 同项目、同日期连续保存 3 次，记录数始终为 1。
- [x] 最终内容为第 3 次保存内容，记录 ID 保持不变。
- [x] 不同日期分别保存为独立记录。
- [x] 无条件重复 `INSERT` 被唯一约束拒绝。

### 4.3 保存失败处理

- [x] 数据库写入位于 `try` 内并被 `await`。
- [x] 成功提示只在事务真正成功后执行。
- [x] 异常进入 `catch`，记录错误并显示用户可理解的中文提示。
- [x] 不存在空 `catch` 吞掉异常。
- [x] `finally` 解除保存锁，失败后允许再次尝试。
- [x] 故障注入测试中事务未留下部分写入。

### 4.4 历史已完成任务保护

- [x] 仅对历史日期中已完成任务的“取消完成”动作弹出确认。
- [x] 今天的任务正常切换完成状态，不弹历史确认。
- [x] 用户取消确认后，页面状态和数据库状态保持不变。
- [x] 用户确认后，才执行数据库更新。
- [x] 修改历史任务不自动回写已保存复盘的统计快照。
- [x] 日期判断复用本地日期规则，避免 UTC 跨日误判。

### 4.5 首次保存复盘确认

- [x] 尚未保存复盘时，首次点击保存弹出确认。
- [x] 用户取消后，不写数据库、不生成快照、不显示保存成功。

## 五、复盘统计快照最终规则

统计快照必须保留。未完成任务会自动顺延，如果历史复盘持续实时计算，原日期任务总数和完成率可能被错误改写。

| 场景 | 页面显示 | 数据规则 |
| --- | --- | --- |
| 尚未保存复盘 | 当前日期实时任务统计 | 每次重新聚焦时刷新 |
| 首次成功保存 | 保存当时的实时统计 | 生成并冻结统计快照 |
| 再次编辑复盘 | 已保存统计快照 | 只更新允许编辑的复盘字段 |
| 后续修改历史任务 | 任务记录按规则纠错 | 不自动回写复盘快照 |
| 首次保存取消或失败 | 仍为未保存状态 | 不生成快照，不显示成功 |

当前 MVP 中，“保存复盘”的产品含义为：

> 保存复盘内容，并确认本日任务统计。
